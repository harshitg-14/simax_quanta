## 1. Project Overview

Simax Quanta is an enterprise-grade Government Knowledge Intelligence Platform designed to ingest, parse, enrich, and query government documents (policies, circulars, schemes, acts, orders) using AI.

The platform is built in phases. This document covers everything completed in **Phase 1**.

## 5. Modules Built

### Module 1 — Document Ingestion Engine

**File:** `app/services/document_parser.py`

Handles three file types:

**PDF:**
- Uses `PyMuPDF (fitz)` to open and extract text block-by-block
- Detects if a page is scanned (empty text) → falls back to `Tesseract OCR`
- Returns full extracted text

**XLSX:**
- Uses `openpyxl` to read all sheets
- Each sheet becomes one chunk, preserving tabular structure

**TXT:**
- Splits on blank lines into paragraphs

**Duplicate Detection:**
- Before saving, checks if a document with the same filename already exists in the DB
- Sets `is_duplicate = "true"` if found (does not block the upload)

---

### Module 2 — Structure-Aware Chunking Engine

**File:** `app/services/document_parser.py`

This is what separates Simax Quanta from a basic document store.

**How it works for PDF:**
- Reads each text block with its font size metadata
- Calculates the most common font size in the document = body text size
- Any span with `font_size > body_size + 2` is classified as a **heading**
- Maintains a `heading_stack` (list of `(font_size, text)` tuples)
- When a new heading is encountered, pops all same-or-smaller headings from the stack and pushes the new one
- This builds a hierarchy like: `Chapter 2 > Section 4 > Clause 1`
- Every paragraph chunk stores the current `heading_path` at the time it was extracted

**Chunk types stored:**
- `heading` — the heading text itself
- `paragraph` — body text under a heading
- `table` — XLSX sheet content (kept atomic, not split)

**Why this matters:**
- When answering a question, the AI can cite exactly *where* in the document the answer came from
- e.g. *"According to Chapter 3 > Section 2 > Eligibility Criteria..."*

---

### Module 3 — AI Metadata Enrichment Engine

**File:** `app/services/ai_service.py`

After a document is parsed, the first 15,000 characters are sent to **Gemini 2.5 Flash** with a structured prompt asking it to return JSON with:

```json
{
  "summary": "2-3 sentence summary",
  "keywords": ["keyword1", "keyword2", ...],
  "doc_type": "policy | circular | notification | act | order | scheme | report | other",
  "department": "issuing department name",
  "version": "version or amendment number",
  "issue_date": "YYYY-MM-DD",
  "effective_date": "YYYY-MM-DD",
  "classification": "public | restricted | confidential"
}
```

All fields are saved directly to the `documents` table. This means every document is automatically catalogued without any manual tagging.

**Retry logic:** If Gemini returns a 503 (high demand) or 429 (rate limit), the system retries up to 3 times with exponential backoff (1s → 2s → 4s).

## 6. Authentication & RBAC

**File:** `app/auth/security.py`

**JWT Flow:**
1. User registers with name, email, password, role
2. Password is hashed with bcrypt before storing
3. On login, password is verified → JWT token issued (8-hour expiry)
4. Token payload contains: `sub` (email), `role`, `name`
5. All protected routes use `Depends(get_current_user)` which validates the token via `HTTPBearer`

**4 Roles:**
| Role | Description |
|---|---|
| `admin` | Full access — can see all users, all audit logs |
| `department_officer` | Can upload and query documents |
| `auditor` | Read-only access to audit logs |
| `reviewer` | Can view and query documents |

**Swagger UI** — After adding `HTTPBearer`, Swagger shows an **Authorize** button where you paste the JWT token to test all protected endpoints.

## 8. Chat / Q&A Flow

When a user asks a question via `GET /documents/chat/ask?question=...`:

1. **Stop-word filtering** — removes words like "what", "is", "the", "how" from the question to extract meaningful keywords
2. **Chunk retrieval** — searches `document_chunks` table for chunks containing any keyword (case-insensitive `ILIKE`)
3. **Context assembly** — top 15 matching chunks are assembled into a context string, each prefixed with its `heading_path`
4. **Gemini Q&A** — context + question + conversation history sent to Gemini 2.5 Flash
5. **Grounded answer** — Gemini is instructed to answer only from the provided context and cite heading paths
6. **Audit log** — question and first 500 chars of answer saved to `audit_logs`
7. **Memory** — question and answer appended to in-memory conversation history (last 10 turns)

## 9. Issues Encountered & Fixed

| Issue | Root Cause | Fix |
|---|---|---|
| `column "doc_type" does not exist` | Old table schema in DB, `create_all` never alters existing tables | Dropped all tables and recreated |
| Chat returning "Information not found" | Stop-word `"what"` was being used as the search keyword | Added stop-word filter list |
| Duplicate `Base` definition | Both `connection.py` and `base.py` defined `Base = declarative_base()` | Removed Base from `connection.py`, all models import from `base.py` |
| No Authorize button in Swagger | `get_current_user` used raw `Header()`, FastAPI didn't register Bearer scheme | Switched to `HTTPBearer` from `fastapi.security` |
| `google.generativeai` deprecation warning | Old SDK deprecated by Google | Migrated to `google.genai` (new SDK) |
| Gemini 503 errors | Google API under high demand | Added retry logic with exponential backoff |
| `pgvector` extension not available | Windows PostgreSQL doesn't ship with pgvector | Deferred to Phase 2 with Docker workaround |

## 10. What's Next — Phase 2

Phase 2 adds **semantic search** using vector embeddings:

- Install `pgvector` via Docker (`pgvector/pgvector:pg16`)
- Add `embedding Vector(1024)` column to `document_chunks`
- On upload: run each chunk through `BAAI/bge-large-en` embedding model → store vector
- On chat: embed the question → nearest-neighbor search (`<=>` cosine distance) instead of keyword search
- Result: finds relevant chunks by **meaning**, not just matching words

**Prerequisite:**
```powershell
docker run -d -p 5432:5432 -e POSTGRES_PASSWORD=Harshit@123 pgvector/pgvector:pg16
```
